将原 v3、历史 v4-pi、新 v4-official 一并整理到 team GitHub，再保存对话检查点。
之前误交付的 Pi 包保留原始源码与哈希，改标为 v4-pi；不再推荐作为此次新提交。

新源码从独立 v3 recovery 复制，继承官方 JSONL-v4 入口及朋友 PR #2 的 Python
数值框架。它是改进后的 team 策略，不是未修改的主办方示例。

## 本次修复

- 完全移除 `CandidateBridge`、`candidate_selector` 及未来外部选择器路径。
- 不引入 Pi、Node、模型 worker、子进程 CPU meter 或构建下载。
- `python:3.12-slim`、空 `build`、`python3 -u agent.py`、仅标准库。
- 保留 Python `urllib` + 异步线程的公告解释和反馈建议两种模型角色。
- 保留 recovery 静态几何缓存、真实 CPU 搜索截止、合法科学基线与一个紧急请求布局。
- 决策成本单位为观测秒：剩余观测秒乘平均决策 CPU 秒，再除剩余真实 CPU 秒。
- 饱和目标重新响应新请求；搜索截止时仍保留合法部分请求进展。
- 最多八步虚拟请求序列，只执行第一步，真实账本只由实际回执更新。
- 更新中英文运行说明、版本名称和默认打包名，消除 Pi 路径歧义。

## 验证

`finalize_delivery.py` 绑定所测源码与最终 ZIP：18 项既有合成测试、3 类 recovery
预算/请求回归、请求召回专项、语法编译和标准库导入检查。实际解压 ZIP 再验证
9/16/25/100 光纤的 Python 子进程、官方动作和光纤几何、合成反馈/resync、两个
确实应用的 localhost HTTP 模型角色，再复跑预算和请求回归。

检查归档无 Pi/Node 文件、无任务数据/测试/凭据，归档与源码逐文件一致。
原 v4-pi ZIP 及其冻结源码哈希再次核验，旧 v3 ZIP 按原版本验证文件核验。

这些是 Windows 本地工程验证，没有真实模型调用、练习/正式评分或隐藏 truth。
完整季平台 CPU 预算、真实模型收益与正式提升仍未建立。尤其短 REQUIRED 曝光
仍可能增加决策次数；最低目录扫描与保底布局也有不可忽略的成本。缓存提速和
正确成本计价针对已确认问题，不能保证 SOTA。

本轮独立委派明确请求 Luna/max，但新子任务收到遮蔽内容，实际路由证明未取得，
记为 `ROUTING_POLICY_VIOLATION`。所采用的源码和测试由主代理直接复核。
