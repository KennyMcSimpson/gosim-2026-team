# v4：v3 修复底座与 Pi 候选评审

基于独立的 v3-recovery 和最新 v2-pi-pro 接口，保留此前版本与评测证据。
修复搜索截止时请求进展丢失、已饱和目标无法召回，以及 CPU 决策成本量纲。

Python 继续负责比赛协议、状态、几何、评分、搜索、CPU 节奏、校验和提交。
Pi 在当前决策中比较 Python 已算出的候选，提交候选 ID、决策 token 和受限理由。
候选包含科学收益、REQUIRED 最后机会、请求奖励与期限、作废风险、均匀度、
program、pointing 和曝光时长。模型不能编造动作或运行代码。

替换必须通过数值条件：估计单位时间收益至少达到原方案的 85%；
短曝光和均匀度替换至少达到 98%。这只是估计收益限制，不保证实际得分无损。
失败、超时、过期或非法选择时采用 recovery 方案，提交前再次校验几何与状态。
多步请求的首步不交给单步评审替换，避免模型错比后续收益。

默认删除旧版异步全局优先级建议。当前方向公告同步解读作为第二个 Pi 环节。
每卡最多 24 次候选评审、8 次公告解读，额度随季节进度释放；每问一次模型、
一次工具提交，单次最多 8 秒，保留 300 秒墙钟余量。故障确认沿用 recovery 门槛。
剩余实际 CPU 不超过 24 秒时停止模型调用；连续三次失败停止重试。
Linux 优先计量容器 cgroup；其他环境读取 Python 与 Node 的实际进程 CPU。
无法取得 worker 计数时，按两核乘调用耗时保守计费。

`AGENT_MODEL_BACKEND=pi-pro` 为默认；`v2` 是 recovery 配原 HTTP 建议器；
`disabled` 为无模型 recovery 路径。模型配置沿用 `OPENAI_BASE_URL`、`OPENAI_MODEL`
及运行时 `OPENAI_API_KEY` / `KIMI_API_KEY`，不把凭据写入任何文件。

平台构建下载校验固定的 Node 22.20.0 Linux x86_64；Pi 依赖已打包并含许可。
打包命令：`python3 pack_agent.py --out ../v4.zip`。
ZIP 用于网页“完整项目”上传，不包含数据、测试、日志、依赖目录或凭据。

工程测试通过不代表整季完成或比赛提升。需要同模型配置下与原 v2 比较总分、科学分、
REQUIRED 缺失、请求完成、作废、CPU/墙钟终止和候选实际应用次数。
