## 1. 结论与优先级

广泛调研后，最值得继续验证的是三种机制，而不是把某个新模型整体塞进调度器：

1. **小型、锚定的结果校准器。** 学习当前策略选中曝光的产出偏差；先证明它预测得更好，再单独检验它改变调度后的整季收益。
2. **少量连贯情景下的短窗滚动调度。** 比较现在观测、稍后观测和替代目标的机会成本，优先处理 REQUIRED 与限时请求。其主要价值来自控制结构，不依赖在线神经网络训练。
3. **有证据的条件提案记忆。** Agent 检索类似条件下的经验，提出少量有界参数或搜索份额建议；数值基座重新生成合法候选、计算收益并执行。JitRL、Memento、CER 可提供结构参考，但历史分数不能自动变成动作优势。

其中第 1、2 项适合先做独立实验；第 3 项须有可比较的外部评估证据。Bandit 策略学习、完整 JEPA world model、LLM 权重 TTT 暂列储备方向。它们分别缺少可信动作奖励与覆盖、任务专属转移训练集、或专门预训练及权重访问条件。

这些是研究选择，尚未晋级为已接受实现。没有论文直接证明上述组合提高 GOSIM 分数；也没有本轮 GOSIM 效果实验。

### 2.2 可观测反馈是什么

当前文档明确 `participant-agent-protocol-v4` 和 `v4-initialize-v1`。上次曝光结果包含 `observe_index`、`assigned_count`、`hit_count`、`hits[{target_id, score}]`。

`hit_count` 是通过光纤与最低高度检查的数量，**不等于正分目标数**；天气或事件可使几何命中的目标得 0 分。未来天气数值不会直接下发。`state_resync` 可撤销过去曝光，重新给出最好分数与请求状态；曝光花掉的时间不返还。请求结果也可能通过 `revised: true` 更正。[当前文档](https://create.gosim.org/survey26/platform/docs)

因此可以构造三个不同监督对象，但不能混写：

| 对象 | 可用监督 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- | --- |
| 所选曝光的正分比例 | 正分目标数 / assigned_count | 当前选择策略下的曝光产出估计 | 纯天气准确度、未选候选的效果 |
| 目标本次曝光得分 | 已返回的 score，结合公开目标属性 | 已执行曝光的质量与产出诊断 | 未执行曝光真值、看到分数即可归因故障 |
| 调度版本净收益 | 外部完整评测分项及终止记录 | 同预算完整版本的比较 | 将终局分数均摊成每个提案的因果奖励 |

天气、仪器、几何和目标构成共同影响 score。即便从未饱和正分 score 反推质量比例，它也只是条件性的混合质量代理；饱和、零分和未命中造成删失，不能识别所有隐变量。

## 4. JitRL：值得借结构，不能直接移植“RL”保证

### 4.1 身份、机制与监督

JitRL 全名为 *Just-In-Time Reinforcement Learning: Continual Learning in LLM Agents Without Gradient Updates*。arXiv 本次用 `2601.18510v4`；[PMLR 官方条目](https://proceedings.mlr.press/v306/li26cv.html)确认 ICML 2026，306:68204–68230。没有独立确认 Spotlight。

论文 §4.1–4.4 的链路是：完成一条 episode，LLM evaluator 分配逐步 reward，再折算 discounted return；存 `(state, action, return)`；相似状态 kNN 估计 V 与按动作筛选的 Q；用 `A=Q−V` 改变基座动作倾向。理论 KL 正则解为：

```text
pi_new(a|s) ∝ pi_base(a|s) * exp(beta * A_hat(s,a))
等价的 raw-logit 形式：z_new = z_base + beta * A_hat
```

这不是单靠实际环境奖励自动学习。LLM evaluator 出错会污染回报与检索。其一致性论证依赖动作覆盖、足够多的样本、状态正则性、无偏噪声及足够慢的策略漂移等条件。短赛程中几个同类曝光不满足这些条件，不能套用渐近改进保证。Limitations 还指出文本状态表示不适合某些空间或时间序列任务。[v4 方法与附录 C](https://arxiv.org/html/2601.18510v4)

### 4.2 公开代码与论文公式不是同一个更新

作者仓库核查固定提交：`143d22185d95fbf633a0befe6861d5e8b732543b`。

- [WebArena 1017–1063](https://github.com/liushiliushi/JitRL/blob/143d22185d95fbf633a0befe6861d5e8b732543b/WebArena/memory_agents/jitrl_agent.py#L1017-L1063)：把候选编号 logprob 转成 `exp(logprob)`，或把自报 confidence 除以 100。
- [WebArena 296–412](https://github.com/liushiliushi/JitRL/blob/143d22185d95fbf633a0befe6861d5e8b732543b/WebArena/memory_agents/jitrl_agent.py#L296-L412)：向概率式分数加归一化优势，而非向 raw logit 加优势。
- [WebArena 1119–1152](https://github.com/liushiliushi/JitRL/blob/143d22185d95fbf633a0befe6861d5e8b732543b/WebArena/memory_agents/jitrl_agent.py#L1119-L1152)：模型返回候选后由 Agent argmax 重排，未把修正写回模型解码器。

论文附录 F 也允许注入检索到的历史动作。候选来源不是只限当前基座生成；但历史动作仍须重新验证当前合法性。上述源码行为不能直接继承 `z+beta*A` 的闭式 KL 结论。

论文的 30 倍以上货币成本节省来自特定 benchmark 比较，不是 GOSIM CPU 或墙钟保证。“无梯度”仍有生成、评估、摘要、检索成本。

### 4.3 对本题应怎样改造

建议只借“受限候选 + 条件经验检索 + 冻结基座”结构。动作单元先定义为有边界的参数模板或搜索份额配置，不用自然语言直接提交 telescope action。

经验条目记录决策时公开状态、提案、实施版本、实际执行范围、反馈与评测 ID。LLM 的解释、confidence、错误归因均作为假设；外部结果才是证据。终局版本分可以检验整个提案组合，不能分配成每个曝光的 Q 值。

若以后具备已知 propensity 的有限动作随机化和可信净奖励，可以另研究 advantage reranking。现阶段无法可靠估计 Q−V，方案名称应是“证据条件化建议/重排”，不声称完成了 JitRL 或自主强化学习。

## 5. 候选 A：小型锚定结果校准

### 5.1 目标与损失

对曝光 i，设分配目标数为 n_i；每个目标的已公开本次曝光正分指示为 z_ij。唯一当前已核实的比例标签是：

```text
y_i = sum_j 1[score_ij > 0] / n_i
p_i = E[y_i | 决策时可见状态、所选曝光与分配组成]
```

不把它改名为天气、REQUIRED 完成概率或“曝光成功”。n=0、结果未到、结果不完整、字段无效不是 y=0；合法零分标签与未知标签分开保存。

标量 p 对该比例的平均目标 Bernoulli 分数为：

```text
Brier_i = p_i^2 - 2*p_i*y_i + y_i
LogLoss_i = -y_i*log(p_i) - (1-y_i)*log(1-p_i)
```

`(p-y)^2` 是比例均方误差，与上述 Brier 差一个仅依赖 y 的项；同一曝光上比较 p 的排序相同，跨不同样本组成时不可混报为同一绝对指标。log loss 需要截断 p 以免数值发散。同曝光目标共享条件，一次曝光是相关块，n 根光纤不是 n 个独立验证样本。

先固定主汇总为曝光等权，另报目标数加权及按 n、program、REQUIRED 构成、可见条件分层的结果。权重在看测试收益前冻结。

### 5.2 最小模型与更新顺序

候选先从全局收缩校准开始，再比较低维修正：

```text
p_cal = sigmoid(logit(clip(p_base)) + g * delta_theta(x, action_summary))
theta 初始为 0；g 初始为 0；修正幅度有限。
```

小特征可以包含公开预报类别、当前简报、program、曝光时长、分配数、亮度/权重分布、几何余量、最近成熟误差与剩余资源。不要使用卡名作条件特征，也不要用执行后统计替换冻结输入。

theta 拟合的是未融合的影子输出，即训练分支用 `g=1`；实际融合 gate 起始为 0，并且只用此前冻结的预测损失决定后续 gate。否则把可训练分支也乘以恒为 0 的 gate，会阻断修正参数的学习。gate 晋级与拟合使用的时间边界必须分别记录。

先用单一慢估计。若开发阶段确实显示短期漂移、成熟曝光足够，再比较近期窗口与全历史估计，并借 ELF 的快慢融合或 ORCA 的近期误差回退；不先引入三层 Fourier 网络。

每轮顺序固定为：先处理此前反馈/撤销；读取当前公开状态；冻结 base/cal/Agent 预测及信息截止时间；执行；下一轮取得对应结果后计分；更新只影响后续预测。不得用更新后参数回头重新生成本轮预测。

反馈刚可见仍可能以后撤销。这里的“成熟”表示当前可关联、曝光完成且结果已送达，不表示永久不可变。保留可撤销的逐曝光记录；删除或替换标签后重放小模型/充分统计量。无法恢复个别贡献时，回到可信锚点或开启新校准 epoch，保留审计日志。

### 5.3 使用方式与失败门

第一阶段仅影子预测。同期 p_base 与 p_cal 在**相同曝光标签**上作预序比较，防止模型只是换了一批更容易目标。

校准器通过影子测试后，动作阶段仍须做完整配对评估。一个全局比例乘到所有候选上可能不改变排序，也可能错误压低 REQUIRED；它不能替代 factor≥阈值的完成判断，更不能把低权重正分等同高净收益。

若没有条件支持、标签明显失配、当前修正过大或资源不足，回退 base。若改善只来自目标构成变化、单张公开卡、标签回看或无法撤销的污染，停止晋级。

## 6. 候选 B：连贯情景下的短窗滚动调度

### 6.1 对应的实际决策问题

REQUIRED 问题需要分别问：还能否达到完成阈值？可见窗口剩多少？稍后好条件是否可靠？现在低质量曝光的边际收益与放弃罚分如何比较？限时请求另有截止、最少完成数和奖励；不能都缩成正分比例。

先用几何、整段最低高度、可用光纤、曝光结束时刻与 deadline 作可行性检查。近似筛选必须采用可信界；启发式只能控制搜索优先级，不能声称安全剪掉必需机会。保留紧急 REQUIRED 的精算通道。

### 6.2 最小场景规划

候选可先用 3–5 条连贯路径：官方描述性预报对应路径、当前条件持续路径、不利偏差路径等。路径在一段时间内保持状态相关，区别空间方向；不能每轮独立随机天气再声称模拟了真实等待机会成本。

这些路径是公开信息约束下的压力情景，不是预测真值。没有校准证据就不赋予虚假的概率；可比较平均情景与保守 regret 标准，选择规则在开发集冻结。路径数不是独立样本数。

对少数候选短窗计算：目标 best-max 增量、REQUIRED 阈值/罚分、请求奖励、均匀度、已知事件及预算机会成本。只执行当前动作，收到新公告、结果、故障或 `state_resync` 后重算。

预测恶化时回退到反应式基座，不把整晚承诺写死。长期价值先用简单终端项表示剩余 REQUIRED 债务与几何机会，再检验增加 horizon 是否值得 CPU。

### 6.3 Agent 分工与可证伪点

Agent 适合把自然语言值班日志转成带原文位置、方向、时效与置信级别的结构化事件，或提出有界情景；数值基座负责合法性、阈值和收益。模糊故障描述不能自动变成已确认异常，更不能直接触发带罚分的 report。

比较同预算下确定性基座、反应式 deadline/slack、单预报短窗、连贯多情景短窗。若多情景收益只来自更大搜索预算，或低质量期等待增加导致 REQUIRED 债务/提前终止恶化，则不支持该机制。

## 7. 候选 C：条件提案记忆与有界适配

最小记忆项是公开条件与可复核结果的关联，不是自由增长的聊天全文：

```text
proposal_id / source_version / protocol_version / visible_context
condition / parameter_delta_or_share_template / evidence_refs
issued_at / expires_at / applicable_state_revision
execution_scope / external_evaluation_receipt / status
```

区分 `proposed`、`executed`、`supported`、`expired/retracted`。检索优先结构化条件与版本兼容性；可先用有限桶或小规模相似检索，BM25/embedding 是后续成本选择。

LLM 可以从失败轨迹提炼“在什么公开条件下发生了什么”，但不能把其归因写成已验证机制。只存成功会丢掉失败边界；只按分数检索会过度复用容易卡。CER 的 ground-truth-success 消融支持外部验证的价值，不证明本题应该删除所有失败。

每轮建议相对**当前基座**计算，不累加为永久漂移；限幅、TTL、状态 revision、请求状态和预算检查全保留。历史具体指向/目标 ID 不直接复用，重新做几何和分配。

跨卡共享运行记忆、外部存储的持久性和同批卡间交流均须另核实运行与公平合约。当前设计默认每卡清空在线统计；开发阶段得到的通用模板需在测试前冻结，不能用 A 卡结果在线污染作为独立验证的 B 卡。

若启用提案影响力，比较无 Agent、同调用预算但不检索、检索后仅影子、检索加有界影响四种条件；必要时加随机打乱记忆对照。保持候选数量与搜索 CPU 一致，避免把额外算力当记忆收益。

## 8. 暂缓方向及启用条件

### 8.1 JEPA 与视觉/LLM TTT

JEPA-TTT §3.3 的目标是执行动作后可见下一图像的 latent；冻结视觉编码器与奖励头，更新预测部分。奖励头有离线标签训练。它不是无监督在线学奖励。测试主要是一次固定、持续的动力学改变，跨 episode 保留优化器与 replay；未验证连续切换和遗忘。

若以后有足够多合法 `(公开状态, 执行动作, 下一公开状态)` 轨迹，可以先做低维结构化转移预测，并检查该辅助任务是否影响规划；没有理由先建视觉 JEPA。还需动作覆盖、源模型与奖励对齐、运行计时以及新条件验证。当前闭环结果校准已经更直接。

TTT-RM 的 residual 是历史表征重构差，不是曝光结果误差；TTT-NTP 的 prompt ridge 写入依赖专门预训练的层；Elastic TTT 的稳定锚仍需视觉重建监督。它们可启发更新与重置边界，不能合并称作“任意模型的无标签漂移恢复”。

### 8.2 Bandit 与 CPU 资源价格

四专家份额若要学习，动作应是有限可执行配置，例如固定的 share vector；只给被用专家记成功会混淆候选生成与最终执行。需要真实抽样概率、上下文、所选配置、实际 CPU 消耗、延迟、撤销与可对齐的净奖励。

EXP4-DALE 的延迟估计还使用历史及反馈到达时对旧上下文的动作概率，并不是“随手乘上 1/propensity”就等价。它比较最优固定策略，没有 CPU 约束。稀疏 CBwK 把 reward 减 resource-price 再加置信项，实际消耗更新价格，但理论依赖线性稀疏模型、稳定条件分布、即时反馈、设计覆盖及腐化条件。官方撤销也不能不加论证地当成该论文的任意腐化。

CPU 影子价格可以作为数值资源调度启发，但必须保留硬额度保护。探索需要花费机会与 CPU；短赛程未必能回本。缺少重叠支持时，离线 DR/IPS 无法比较未执行配置。

### 8.3 主动观测与区间

可研究“何时值得付出曝光成本以辨别当前条件”，但比赛没有额外免费传感器接口；该成本就是失去其他目标机会。先把它作为短窗调度中的信息价值压力测试，不额外发明动作。

延迟 ACI 可提供曝光队列与成熟后覆盖诊断；固定延迟条件不能自动覆盖可变延迟、选择性标签和 revised 结果。经验区间应标注当前策略条件，不声称跨所有候选有保证。

## 9. 预算与生命周期合同

| 项目 | 最小合同 | 失败处理 |
| --- | --- | --- |
| 训练/检索 CPU | 计全部进程与线程，按 speed_factor 标准化；与搜索共同入账 | 削减情景、窗口、检索，再回退 base |
| 增量预算 | 开发试验可从每卡新增不超过 45 标准化 CPU 秒的上限起步；这是待锁定试验参数，不是实测可行性 | 完整季基座没有余量则禁用适配 |
| 墙钟与网络 | 等待不计 CPU，但设调用截止、重试上限和 wall_remaining_seconds 安全余量 | 429 有界等待重试；超时返回完整基座动作 |
| 输入与反馈版本 | 冻结 input hash、cutoff、observe_index、目标集合、prediction/proposal/model 版本 | 不匹配只记 unknown，不能凑标签 |
| 更正与撤销 | 一条 outcome 有版本；替换贡献，不追加为新独立样本 | 重放统计，无法恢复则可信锚/新 epoch |
| 起始与跨卡 | 每卡在线状态重置；通用先验开发阶段冻结 | 不用卡名、未来 truth 或测试后规则 |
| 接受门 | 独立损失或同预算配对结果支持后才提高影响力 | 小样本、过期、异常时权重归零 |

线上 CPU 可行性只能由同容器计时证明。ORCA 的 B200、RACE 的 GPU 工作流、ELF 的矩阵更新或 JitRL 的美元对照均不能替代本题计时。外部服务也需报告调用、费用、失败率和墙钟；仅迁移计算位置不证明机制必要。

## 10. 最小验证设计

### 10.1 主张、资源与隔离

待验证主张分别是“结果预测改善”“同预算整季得分改善”“新条件可迁移”。当前有源码、官方公开资料与既有结果包；没有新增配对实验、可靠未选动作真值、官方隐藏卡或新机制的 CPU 证据。

本轮只定义合同，不执行数据划分、训练或评分。后续测试必须绑定场景/日志/协议版本；10 月 6 日值班日志更新前后不视为相同实验环境。

| 层级 | 隔离单位与作用 | 接受/停止标准 | 当前状态 |
| --- | --- | --- | --- |
| 合同检查 | 协议与 outcome ID；可由合成零分、缺失、撤销例确认 | 无泄漏、重复或撤销污染；失败即停止效果实验 | 仅研究定义 |
| 影子预序 | 同策略相同曝光上比较冻结预测，先预测后更新 | 相对全局收缩与 base 改善 proper loss，报告块不确定性；仅特定桶有效就缩小主张 | 未执行 |
| 完整配对季 | 相同公开场景/日志/引擎、相同预算，各自跑完整轨迹 | 主净分增量及分项支持；不增加错误/提前终止；预测损失不能替代净分 | 未执行 |
| 未调参条件 | 按夜次/天气过程/场景家族隔离；拟合、gate、阈值、memory 均冻结 | 收益超出运行波动且未出现未解释的大卡级损失；不足则不声称泛化 | 未执行 |
| 官方外部 | 仅经另行授权的正式外部结果；隐藏卡由主办方提供 | 本地机制和线上表现分别报告；隐藏外推须真实结果 | 无本轮评测 |

公开八卡已被团队反复查看，不能叫全新独立测试集。新生成且不参与调参的合法压力场景可支持有限条件外推，不等于官方隐藏 E–H。评测三次只测程序波动，不会把固定卡变成三种新天气世界。

### 10.2 对照与分项

先各自验证 A、B、C；通过后才做必要交互，避免一次改三个机制无法归因。

| 比较 | 必要对照 | 关键分项 |
| --- | --- | --- |
| A 校准 | base、全局收缩、条件修正；初期全为影子 | 同曝光 proper loss、标签数、条件覆盖、撤销 |
| B 调度 | base、反应式、单预报短窗、连贯情景短窗 | REQUIRED 完成/罚分、请求奖励、best-max 增量、等待、CPU |
| C 记忆 | 无 Agent、同调用不检索、检索影子、检索有界 | 实际调用成功、提案执行、有效期、来源、整季净分 |
| A+B | 冻结各单项后比较组合与单项 | 修正是否改变候选排序，是否只是增加算力 |

共同报告总分、科学分、REQUIRED、请求、均匀度、report 得失、作废、完整模拟覆盖、退出原因、标准化 CPU、墙钟和模型回退。失败/超时卡不得从平均值中删去。

置信计算按完整季或相关天气/夜次块；四卡或八卡样本少，明确逐卡差值和运行方差，不能把上千目标当作上千独立实验。预测阶段同标签配对；策略阶段动作序列会分叉，比较完整轨迹，不能只回放旧策略已选动作。

### 10.3 停止与降级

- 主目标净分没有可区分于运行波动的增量，或收益只在调参卡上出现：保留工程产物，停止效果晋级。
- 标签/propensity/日志版本缺失：相应反事实或迁移主张停止；已选策略下的描述性校准仍可另报。
- 新增计算挤掉基座整季运行、更多 agent_error 或越过预算：关闭新模块。
- 正分比例提高而 REQUIRED、请求或科学净分下降：代理奖励失配，不能继续用“准确率提升”解释策略成功。
- 记忆证据只来自 LLM 自评、相同结果重复计数或测试后提炼：撤回相关条目，重建合法隔离。

数值效果门槛、最大允许卡级退化、CPU/墙钟安全余量应在实际实验前锁定；本文不把任意百分比当成已协商或已测门槛。
